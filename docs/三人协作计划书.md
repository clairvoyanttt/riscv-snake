**交付目标**　在课程版 Logisim 中打开团队电路，启动时钟，即可用按钮玩一局 16×16 贪吃蛇。演示者能按键转向、吃食物得分、暂停、继续、撞墙或撞身结束，并一键重新开局。

## 3. 三方共用接口

### CPU 与外设

游戏用 `lw/sw` 读写外设。下表是 **CPU 字节地址**，全部按 4 字节对齐。A 在完整的 32 位数据地址上译码，再把外设内的字索引 `(地址 − 0x1000) >> 2` 给 B。普通数据 RAM 使用低地址 `0x0000–0x0FFF`。两个空间允许低地址位相同，写使能必须互斥。

| CPU 地址 | 字索引 | 读写约定 |
|---|---:|---|
| `0x1000` EVENTS | 0 | 读低 6 位待处理按键，位 0 至 5 依次是上、右、下、左、开始/暂停、重开。按下沿置位，保持至软件确认 |
| `0x1004` ACK | 1 | 写 1 清对应事件位。C 将刚读出的掩码原样写回；同一拍新按下的事件优先保留 |
| `0x1008` SCORE | 2 | 写低 8 位无符号分数。用两位十六进制数码管显示，面板标注 HEX；吃第一个食物显示 01 |
| `0x100C` STATE | 3 | 写 0 待开始、1 运行、2 暂停、3 失败、4 胜利。面板显示对应文字标签的状态灯 |
| `0x1010` FOOD | 4 | 位 8 为显示使能；低 8 位为 `16*y+x`。例：写 `0x188`，食物出现在 (8,8)；写 0 隐藏 |
| `0x1040 + 4*y` ROW | 16–31 | 写第 y 行蛇身的 16 位掩码。bit 0 最左、bit 15 最右；y=0 在顶端。写一行只替换这一行 |

SnakeIO 输入引脚为 `clk[1], reset[1], index[5], wr[1], wdata[32]`，输出为 `rdata[32]`。按钮和显示元件由 B 放在其电路内；A 在整机中提供能直接操作和观察的游戏面板（第 5 节说明）。`wr` 仅在外设区有效写时置 1，寄存器在上升沿采样；读数据为组合输出，A 只在读外设时选入 CPU。保留索引读零、写忽略。硬件复位清事件、分数、状态、食物使能和所有行。

### 单周期 CPU、时钟与复位（A/B 共用）

整机入口固定为 A 副本中的 **◇单周期RISC-V**，其中放置一个 SnakeIO 实例。六个按钮、点阵、分数和状态灯都放在 B 的 SnakeIO 画布。演示时从 CPU 顶层进入**这个正在运行的实例**操作。A 在运行说明中记录本版本实际使用的菜单或导航步骤，并附一张面板图。

现有 CPU 自带时钟、13 位计数暂停逻辑和 `CLK` 信号，没有独立 reset 输入。A 把 SnakeIO.clk 接到 CPU 的有效 `CLK`，演示时将计数暂停控制位置 0，开启连续时钟。用诊断 ROM 检查连续写两个不同地址时，每条 `sw` 恰好锁存一次正确的数据。SnakeIO.reset 高有效，B 在 IOTest 中驱动它；A 在整机接常量 0。首次启动和重新装 ROM 后用 Logisim 的“仿真复位”（Ctrl+R），从入口运行初始化。游戏中的“重开”由软件处理，CPU 继续执行；暂停只暂停蛇的移动，输入采样仍需时钟。验收时分别测试仿真复位和局内重开。

### 汇编约定与 RAM 布局（A/C 共用）

诊断和游戏发布 ROM 统一使用以下 **20 条项目指令**。该集合取课程控制器的基础运算、访存和跳转，足以实现全部玩法。应用启动、显示及按键都走本文接口，因而省去 `ecall`、中断指令以及电路中的 `lh/bltu` 扩展。

| 用途 | 允许的机器指令 |
|---|---|
| 寄存器运算 | `add sub and or slt sltu` |
| 立即数运算 | `addi andi ori xori slti slli srli srai` |
| 数据访存 | `lw sw` |
| 控制流 | `beq bne jal jalr` |

写 `1 << x` 时从 1 开始循环执行 `slli ...,1`；用 `slt` 配合 `beq/bne` 做有符号比较。子程序用 `jal ra,label` 调用、`jalr zero,0(ra)` 返回。发布源文件优先直接写表中指令；使用伪指令时逐条检查 RARS 的 Basic 列或反汇编清单。特别留意变量移位 `sll/srl/sra`、`blt/bge`、寄存器 `xor`，以及可能展开出 `lui/auipc` 的 `li/la/call`。验收依据是最终机器指令是否全部在表内。

| CPU 字节地址 | 分配及验证 |
|---|---|
| `0x0000–0x03FF` | 蛇身环形队列，256 项，每项 4 字节，槽 255 在 0x03FC |
| `0x0400–0x043F` | 16 行占用掩码，每行 4 字节 |
| `0x0440–0x04FF` | 游戏状态。从 0x0440 起按字顺序放头索引、尾索引、长度、已执行方向、待转方向、食物格、分数、运行状态，其余留给计时等变量 |
| `0x0500–0x07FF` | 预留工作区，可用于独测记录 |
| `0x0800–0x0FFF` | 栈区。入口设 sp=0x0FF0，保持 16 字节对齐，向低地址增长。建栈帧先减 sp 再写，最深处应 ≥0x0800 |

硬件按字节地址的 [11:2] 位选择 RAM 字。发布程序只导出 `.text`，游戏入口显式初始化 RAM。以下三条将 sp 设为 0x0FF0，并避开 `addi` 有符号 12 位立即数的限制。

```asm
addi sp, zero, 1
slli sp, sp, 12
addi sp, sp, -16
```

### 游戏规则

坐标从左上角 (0,0) 到右下角 (15,15)。初始蛇尾到蛇头依次为 (5,8)、(6,8)、(7,8)，方向向右，首个食物在 (8,8)。待开始时静止，按开始后第一步就能演示得分。每吃一次加 1 分、长一格；撞墙或撞仍被占用的身体后停住并亮失败灯。占满 256 格时亮胜利灯。

游戏运行时每个移动周期最多接收一个有效转向，以**上一次实际移动方向**判定禁止掉头。重开优先于所有输入，恢复待开始；开始/暂停键其次，暂停与继续均保留棋盘。多个方向同时挂起时按上、右、下、左依次取首个有效转向。按住一个键只产生一次按下事件。

## 4. A 的操作单 · 把 CPU 接入游戏

- [ ] **建可运行副本。** 复制 CPU 电路及两个 JAR 到 system 目录，使用课程版 Logisim 打开副本。将游戏使用的单周期电路设为入口或在运行说明标出入口，确认能观察 PC 随时钟前进。
- [ ] **接访存。** 从单周期图中沿 `ALUResult`、`MemWrite`、`MDin`、`MemData` 找到原 RAM 的地址、写使能、写数据与加载回写路径，用探针核对 `sw/lw` 时序。截取 RAM 地址低位之前译码 `0x1000–0x107F`；把 RAM 写使能与外设写使能分开。给读回路径加选择器，保留原 RAM 的字节地址到字地址转换。RAM 写使能限定在 0x0000–0x0FFF；越界写忽略。I/O 口统一按字读写。
- [ ] **独立验证。** B 尚未交付时，在外设读端临时接常数 2（右键），在写端接探针。编写 io-smoke 程序：先写 RAM[0]=0x55，再读 EVENTS、写 ACK、写 SCORE=1，并交替向 ROW0 写 1、ROW15 写 0x8000。读回 RAM[0] 仍为 0x55；另在与 SCORE 同低位的 RAM[0x08] 写入哨兵，再写 SCORE，哨兵应保持。探针可见正确字索引和数据。
- [ ] **联调。** 导入 B 的 SnakeIO，连接五个输入和读回端，移除临时常量，实际按右键后确认诊断程序能读到 2 并清掉。装入 C 的游戏 ROM，先走一格，再开连续时钟。记录本机可玩的时钟设置，和 C 一起调整移动间隔。
- [ ] **交付。** 使最终电路打开即可进入游戏，或提供不超过五步的装载说明。交付整个 `snake/` 目录。外设库引用相对于主电路为 `../io/SnakeIO.circ`，两个 JAR 放在主电路旁，ROM 随 game 目录交付。检查保存后的库描述，清除本机盘符和用户目录依赖；在另一台机器或原路径不可用的独立环境中，从复制件启动课程版 Logisim，打开 system/SnakeSystem.circ 并完成第 7 节记录。

## 5. B 的操作单 · 把按键和点阵做成独立外设

- [ ] **建立测试台。** 在 SnakeIO.circ 中建 SnakeIO 和 IOTest 两个子电路。IOTest 用开关给定 index/wdata/wr/reset，用单步时钟触发写入，用探针显示 rdata。约定按键在 CPU 时钟上升沿采样，连续时钟下操作；单步测试时按住并跨过采样沿。
- [ ] **做输入。** 六个按钮分别检测从松开到按下的变化，以 6 位寄存器保存待处理事件。每拍更新为 `(旧事件 & ~本拍确认掩码) | 新按下位`。按住暂停跨三拍，读值应一直为 0x10；确认后继续按住应为 0；松开再按应重新出现 0x10。另测同拍确认旧右键并按下上键，上键仍保留。
- [ ] **做显示。** 选用 16×16 DotMatrix，输入类型设为 Row（按行），用 16 个 16 位行寄存器驱动点阵，按 index 选择写入行。蛇身常亮，食物位置闪烁（由同一 clk 计数分频。以有效上升沿频率 f 为准，计数器 bit k 的完整闪烁频率是 f / 2^(k+1)。例如实测 f=512 Hz 时取 bit 7 得 2 Hz；记录演示时实测频率与抽头），两者合成后送点阵。先在测试台验证两个对角点、整行和闪烁食物，再接分数及五个状态灯。
- [ ] **验证可操作面板。** 玩家应能在同一画面操作按钮、看棋盘和分数。A+B 按第 3 节从顶层进入正在运行的 SnakeIO 实例，按右键，回到 CPU 确认诊断程序读到 2。B 单独写 ROW0=1 后先确认左上亮，再清 ROW0、写 ROW15=0x8000 确认右下亮；最后单点 (2,5) 排除行列互换。若方向有误，在 B 的显示接线处调整，并在原理图标注行顺序及是否倒序接线。
- [ ] **交接。** 在外设测试文档附引脚方位、时钟边沿、复位方式和实测结果。交给 A 时用 ROW0=1、ROW15=0x8000、FOOD=0x188、SCORE=0x0A、STATE=2 演示，预期为左上和右下亮点、(8,8) 闪烁、显示 0A、暂停灯亮。

## 6. C 的操作单 · 让自制 CPU 运行游戏

- [ ] **先做确定的第一局。** 将程序按 `init_game`、`poll_input`、`step_game`、`place_food`、`render_changes`、主循环组织。用普通 RAM 保存 256 项蛇身环形队列（每格 1 字）、16 行占用掩码和少量状态。在源文件开头列出 RAM 区间及栈顶，启动时显式初始化。避免依赖 RARS 默认数据段地址或系统调用。游戏状态均由 CPU 程序更新。
- [ ] **实现一步移动。** 算新头坐标，先查边界，再判是否增长；普通移动允许进入本步即将移走的尾格。发生碰撞时保留上一帧。成功移动后更新队列、掩码和被改变的行；头尾在同一行时把最终掩码写回一次。初始第 8 行为 0x00E0；第一次向右吃食后应为 0x01E0，长度 4、分数 1。
- [ ] **放食物。** 首个食物固定，其后从变化的候选格开始顺序环绕查找空格，最多检查 256 格。长度达到 256 就隐藏食物、置胜利并停止移动。该方法便于构造“只剩一个空格”的测试。
- [ ] **接控制和节奏。** 循环读取 EVENTS 并写 ACK，立即处理重开、暂停和继续。把移动间隔集中为一个可调常量，等待移动期间继续轮询输入；暂停时仍响应控制。软件重开要清掉旧的 16 行、旧分数和旧食物，再绘制初始局面。常规移动只写变化行，避免整屏逐格刷新。
- [ ] **独立验规则。** 在临时测试入口用给定方向调用相同的 step_game，以 RAM 或寄存器观察结果；外设读写集中到少数例程，独测时可替换成内存记录。覆盖首食增长、禁止掉头、穿入正在移出的尾格、撞身、四边撞墙、暂停时坐标不变、重开清屏、只余一空格及满盘胜利。记录输入、预期与实测，保留可复现的测试入口或脚本。
- [ ] **导出 ROM。** 用课程版 RARS 选择 Compact, Text at Address 0（CompactTextAtZero），地址 0 的第一条指令即游戏入口。课程 CPU 的 ROM/RAM 分离，而 RARS 的这个配置将低地址分给代码。规则独测可用 Compact, Data at Address 0（CompactDataAtZero）重新汇编测试入口，用低地址 RAM 记录输出，屏蔽真实外设访问；最终切回 Text at Address 0 重新汇编游戏。导出 text 段每行一个 32 位机器字，首行加 `v2.0 raw`，总数不超过 1024 字。检查伪指令实际展开的机器指令受该 CPU 支持；例如 MMIO 基址 0x1000 可用 `addi t0,zero,1` 接 `slli t0,t0,12` 构造。把**游戏入口版** asm、hex 一起交 A，在整机跑通首食后记录采用的 RARS 配置。

| M2 CPU 驱动外设 | A+B | 真按钮经 CPU 读入，CPU 写 ACK 后事件消失；真实点阵显示诊断图，RAM 哨兵保持 | A 看完整地址、写使能和读回选择；B 看 index、时钟、点阵方向 |
| M3 可玩的一局 | A+C，B 观察 | 新局待开始，按开始后吃首食得 01；转向生效、掉头无效；暂停至少两个移动间隔棋盘不变，再按可继续；撞墙停住，重开恢复初始蛇 | C 看状态、移动间隔及行掩码；A 对照 PC 和外设总线；B 对照寄存器与画面 |
| M4 队友复现 | 换一人按说明操作 | 在另一份目录从关闭状态打开系统，独立玩完一局。记录使用的时钟频率、约每秒移动格数，以及按键是否容易漏按 | 帧率过低先查是否整屏重绘，再一起调仿真时钟和软件间隔 |

**可选展示扩展**　M4 通过后若团队还有时间，可让 B 评估课程版 Buzzer，用短音区分吃食和碰撞；地址与触发方式另行约定，基础版本按现有接口验收。

**展示顺序**　B 用半分钟演示按钮、点阵与状态灯。C 边玩边演示吃食增长、暂停和碰撞。A 在一次转向时展示 CPU 读取 EVENTS 和写入 ROW 的过程，说明画面如何随汇编程序执行而变化。每个人都能把自己做的模块对应到观众刚才看到的操作。

**交接回报格式**　每个 Agent 结束时报告五项：交付文件、已实现的接口、实际运行的测试和结果、尚未验证的项目、下一位队友的复现步骤。只有实机或仿真里实际观察到的项目才标记通过。
