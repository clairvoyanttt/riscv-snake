# A 阶段运行与交接

用户已约定由 Agent 完成模拟测试，最终 GUI 操作和试玩由用户进行。以下手动步骤供用户验收使用，既有 GUI 打开记录只表示开发时观察，最终人工验收仍待用户完成。

## 当前交付

A 的独立 CPU/MMIO 阶段已实现，位于 `system/SnakeSystem.circ`。主电路为 `◇单周期RISC-V`，指令 ROM 内嵌 `io-smoke.hex` 的 37 个机器字。两个依赖 JAR 与主电路放在同一目录，均用相对路径引用。电路沿用课程 CPU，新增 SnakeBus 地址译码、读回选择和诊断锁存输出。

此阶段外设读端为临时常数 2。B 的真实按钮/点阵和 C 的游戏 ROM 尚待接入。诊断程序运行到循环后保持结果，便于查看。分数等外设写事务现在通过探针检查。

## 五步运行（供用户最终操作验收）

1. 用课程版 `logisim-hust-20200118.exe` 打开 `system/SnakeSystem.circ`。左侧进入 `◇单周期RISC-V`。
2. 按 Ctrl+R 仿真复位。图中右上角计数暂停控制位保持 0。检查 PC 从 0 开始。
3. 在“电路仿真”菜单设合适时钟频率，按 Ctrl+K 开启时钟。本机 GUI 已运行，运行中频率显示约 2.43 KHz；实际速度由电脑决定。
4. 稍候按 Ctrl+K 停止时钟。查看主画布右下方 A 诊断区域，课程版输出引脚显示二进制，下表用十六进制列出等价值。必要时调整窗口底部缩放并滚动画布。
5. 核对下表。再次演示时，先 Ctrl+R，再 Ctrl+K。

| 输出引脚 | 预期十六进制值 | 含义 |
|---|---|---|
| A_RESULT | 0000600d | 程序比对成功 |
| A_EVENTS | 00000002 | CPU 读到了临时按键值 |
| A_RAM0 | 00000055 | RAM 字节地址 0 的哨兵保持 |
| A_RAM8 | 00000066 | RAM 字节地址 8 的哨兵保持，外设 SCORE 写入未覆盖它 |
| A_WRITE_COUNT | 06 | 恰好六次外设写入 |
| A_LAST_INDEX | 1f | 最后一笔写第 15 行 |
| A_LAST_DATA | 00008000 | 最后一笔行掩码 |

主画布原有八位显示器由课程 ecall 输出驱动，诊断程序的结果看 A_RESULT 等新增引脚。源程序执行失败会将 RAM 字节地址 0x50C 写为 0xFFFFFFFF，未运行到成功指令时 A_RESULT 保持零。

诊断锁存器按这份 ROM 的 PC 位置触发。装入游戏 ROM 后，它们只供 A 调试，不承担游戏状态显示，也不作为游戏验收结果。

## 六次写入

| 顺序 | CPU 字节地址 | SnakeIO.index | 数据 |
|---|---|---:|---:|
| 1 | 0x1004 | 1 | 0x00000002 |
| 2 | 0x1008 | 2 | 0x00000001 |
| 3 | 0x100C | 3 | 0x00000002 |
| 4 | 0x1010 | 4 | 0x00000188 |
| 5 | 0x1040 | 16 | 0x00000001 |
| 6 | 0x107C | 31 | 0x00008000 |

第 5、6 次由相邻两条 sw 完成。原生测试在每个有效时钟上升沿前采样 index/wdata，逐笔断言以上顺序和值；后续空转仍只计六次。

## 给 B 的接入操作

1. B 将 `SnakeIO.circ` 放在 `snake/io/`，交付的主功能子电路名为 SnakeIO。A 用“工程→加载库→Logisim 库”导入，保存后的相对引用应指向 `../io/SnakeIO.circ`。
2. A 在主电路加入一个 SnakeIO 实例，按引脚标签连接下表。使用 B 提供的引脚方位图，接好后逐个检查位宽。
3. 删除诊断区域的临时常数 2 及其输出导线。保留 `SNAKE_IO_DATA` 网络，用 B 的 rdata 驱动，避免与常数形成双驱动。其他 ONE、ZERO 常数供诊断电路使用。
4. 进入主电路中的 SnakeIO 实例操作按钮。诊断程序只执行一次读取，需在复位后保持右键并运行到读取指令，检查 EVENTS 为 2。确认 ACK 后的事件清除行为，要用 B 的测试台或后续轮询程序观察；常数阶段尚未验证这一行为。

| 顶层网络或常数 | B 引脚 | 位宽 |
|---|---|---:|
| CLK | clk | 1 |
| 常量 0 | reset | 1 |
| SNAKE_INDEX | index | 5 |
| SNAKE_IO_WR | wr | 1 |
| MDin | wdata | 32 |
| SNAKE_IO_DATA | rdata（B 输出） | 32 |

SnakeBus 是 A 的组合桥，只处理地址及写使能，不存储按钮或显示状态。reset 的定义和 ACK 同拍优先级继续按协作计划书执行。

## 给 C 的接入操作

1. C 按计划书交付 `snake/game/snake.asm` 和 `snake.hex`，从地址 0 开始，实际机器指令限计划中的 20 条。
2. A 在主电路右击指令 ROM，选择加载镜像，装入 C 的 hex。保持数据 RAM 与 ROM 分离。
3. Ctrl+R 后运行。C 的入口负责初始化队列、行掩码、状态和栈。
4. 配合 B 的真实外设，依计划检查首食、转向、暂停、碰撞和重开。移动速度与按键手感在此阶段由 A/C 一起调整。

## 复现原生测试

测试直接调用课程版 Logisim 的电路传播引擎。需要 Java 与 JDK 编译器，或 Java 8 加 Eclipse ECJ 4.6.1 编译器。以下命令从仓库根目录运行，替换成自己电脑上的工具路径。

```powershell
# 已安装 JDK、java 和 javac 在 PATH 上时
./snake/system/checks/test-native.ps1 -LogisimExe 'D:/硬件/logisim-hust-20200118.exe'

# 本机实际采用的 Java 8 + ECJ 方式（编译器是工作区临时工具）
./snake/system/checks/test-native.ps1 `
  -LogisimExe 'D:/硬件/logisim-hust-20200118.exe' `
  -JavaExe 'D:/Program Files/Java/jre 1.8.0_451/bin/java.exe' `
  -CompilerJar 'D:/硬件/tmp/snake-a/ecj.jar'
```

预期两行 PASS，进程退出码为 0。测试覆盖 11 组桥接地址/读写向量、逐笔外设事务、真实 RAM 内容及最终完成标记。它使用当前内嵌的诊断 ROM，装入游戏 ROM 后要先恢复诊断 ROM 再运行此测试。

```text
PASS SnakeBus: 11 address/write/read vectors
PASS CPU: smoke ROM, RAM isolation, 6 writes, result 0x600d
```

重新生成诊断 hex 可运行下列命令。随后在 GUI 重新装载该 hex 并保存主电路，让内嵌 ROM 与源文件保持一致。

```powershell
./snake/system/assemble-smoke.ps1 `
  -RarsJar 'D:/硬件/2026秋硬件综合训练课设资料发布包/RISC-V汇编工具与测试用例5.0/rars_f0c874c.jar'
```
