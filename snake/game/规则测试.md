# C 阶段：游戏软件、规则独测与 ROM 导出

本文对应当前仓库分支 `feat/snake-game`。计划书第 6 节的五项操作全部落地，规则独测在其自建硬件模型上跑通 23 项。整机实玩（M3）仍需 B 的真实外设接入后完成。

## 1. 交付文件

| 文件 | 用途 |
|---|---|
| `snake/game/snake.asm` | 游戏源程序，含主循环、外设访问、规则三个区段 |

| `snake/game/规则测试.md` | 本文，含测试记录与交接 |

## 2. 程序结构

入口 `_start` 建立栈、三个基址寄存器后调用 `ig_init`，随后进入 `ml_loop`。主循环本身就是移动计时器：每轮先轮询按键，再按状态递减计时，减到零才走一步，因此等待移动期间按键照样被采样。

| 子程序 | 职责 | 被谁调用 |
|---|---|---|
| `ml_loop` | 主循环：轮询 → 状态判断 → 计时 → 一步移动 → 重装计时 | 入口 |
| `ig_init` | 冷启动与局内重开：清 16 行、写初始蛇身与状态、写 SCORE/FOOD/STATE | `_start`、`pi_poll` |
| `pi_poll` | 读 EVENTS、把刚读到的掩码原样写回 ACK、按优先级处理重开／开始暂停／转向 | `ml_loop` |
| `sg_step` | 一个移动周期：边界、占用、尾格豁免、移尾或增尾、食物、只渲染变化行 | `ml_loop` |
| `sh1_bit` | 用循环 `slli` 造 `1 << x`（电路不支持变量移位） | `sg_step` |

寄存器约定：`s0=0x1000`（MMIO 基址）、`s1=0x0400`（16 行掩码基址）、`s3=0x0440`（状态基址）、`sp=0x0FF0`。三者都在 `_start` 用 `addi` + `slli` 构造，不依赖 `lui/auipc`。

### RAM 与状态布局（与计划书第 3 节一致）

| 字节地址 | 内容 |
|---|---|
| `0x0000–0x03FF` | 蛇身环形队列 256 项，槽 i 在 `4*i` |
| `0x0400–0x043F` | 16 行占用掩码，第 y 行在 `0x400+4*y` |
| `0x0440` | 头索引 |
| `0x0444` | 尾索引 |
| `0x0448` | 长度 |
| `0x044C` | 已执行方向 |
| `0x0450` | 待转方向 |
| `0x0454` | 食物格 `16*y+x` |
| `0x0458` | 分数 |
| `0x045C` | 运行状态 0 待开始／1 运行／2 暂停／3 失败／4 胜利 |
| `0x0460` | 移动计时器（剩余轮询次数） |
| `0x0464` | 转向锁：本周期已接受一个转向则置 1 |
| `0x0468` | 第二条待渲染行的行偏移 |
| `0x0500–0x07FF` | 预留工作区（独测可把 `s0` 设成 `0x0500` 让外设写落到这里） |
| `0x0800–0x0FFF` | 栈区，入口 `sp=0x0FF0` |

方向编码 0 上、1 右、2 下、3 左；格值 `cell = 16*y+x`，行掩码 bit x 对应横坐标 x。

## 3. 规则实现要点

**一步移动的次序**：取待转方向为已执行方向并清转向锁 → 由头格算新头格 → 边界 → 占用 → 移尾或增尾 → 置头位并入队 → 吃食与放食物 → 只写变化行。碰撞时直接写 STATE=3 返回，不动任何队列与掩码，画面即保留上一帧。

**尾格豁免**顺序上先判食物、再判占用、最后判尾格，所以"普通移动进入本步即将移出的尾格"成立；同一格被清尾位又置头位时，先清后置，最终仍是点亮（用例 T4 覆盖，头尾同行的最终掩码只写一次）。

**掉头判定**用 `xori 2` 求反方向，与"上一次实际移动方向"比较。按键扫描把方向位右移一位逐个试探，遇到掉头就跳过继续试下一位，因此 `dir=下` 时同拍按 `上+右` 会取到右而不是两者全丢（用例 T21）。一个移动周期最多接受一个转向，靠 `0x0464` 的转向锁实现（用例 T15）。

**食物**：首食固定 `(8,8)`。吃食后从新头格开始按 `+1` 环绕扫描最多 256 格找空格，写 `FOOD = 0x100 | cell`；长度到 256 则 `STATE=4` 且写 `FOOD=0` 隐藏。扫描会绕回低位格（用例 T19）。

**重开与复位**：重开优先级最高，同拍的开始键被丢弃（用例 T12）。`ig_init` 先清 16 行、清分数，再写 FOOD，最后写 STATE，因此"看到 STATE 回到待开始"就说明面板已经一致。冷启动同样走 `ig_init`，所以 Ctrl+R 后无需外部预置 RAM。

**节奏**：`MOVE_TICKS` 是文件顶部的唯一速度常量。暂停只冻结计时器，恢复时重装；按键采样一直在跑，硬件事件保持到 ACK，所以不会漏按。

## 4. 导出 ROM

```
./snake/game/assemble-snake.ps1 -RarsJar <课程版 rars_f0c874c.jar>
```

脚本内部固定为 `nc a ae1 mc CompactTextAtZero dump .text HexText`，即 RARS 的 **Compact, Text at Address 0**，只导出 `.text`，地址 0 的第一个字就是 `_start`。输出 244 字（上限 1024），每行一个 32 位机器字。

用到的机器指令共 14 条，全部落在计划书 20 条白名单内：

`add addi and andi beq bne jal jalr lw or slli srli sw xori`

`sub slt sltu ori slti srai` 未用到。变量移位、`xor`、`blt/bge`、`lui/auipc`、`ecall` 一处也没有：`1<<x` 走 `sh1_bit` 循环，`~mask` 用 `xori -1`，MMIO 基址用 `addi 1` + `slli 12` 构造。白名单不是靠人眼确认，而是 `run_rules.py` 逐字解码断言，任何伪指令膨胀都会当场报错。

## 5. 规则独测

计划书建议用 `CompactDataAtZero` 重编一个测试入口。这里换了一条更省事、覆盖更全的路：直接对**发布用的 `snake.hex`** 跑一个只实现那 20 条指令、加 MMIO 契约的最小 CPU 模型，按键按硬件的按下沿锁存模型驱动。好处是不必维护第二份汇编入口、测的就是要装进 ROM 的那份镜像。

A 阶段电路的 EVENTS 读端目前接常数 2，无法注入开始／重开／转向，所以整机层面的规则验证留给 M3；A 已经跑通的诊断 ROM 证明这 20 条指令在真实 CPU 上能执行，本阶段补的是"软件按规则用它们"。

```
python snake/game/tests/run_rules.py
```

预期末行 `23/23 checks passed`。用例、输入与实测：

## 6. 移动节奏标定

单周期 CPU 一条指令一个时钟，所以"周期数 = 指令数"。实测 `MOVE_TICKS=60` 时两次移动之间 1170–1182 周期，摊到每次轮询迭代约 19.7 周期。A 在课程版 GUI 记录时钟约 2.43 kHz，对应 **每步约 0.49 s，约每秒两格**。

调参公式：`MOVE_TICKS ≈ 目标秒数 × 实测时钟频率 / 19.7`，取值保持 1–2047（`addi` 的 12 位有符号立即数上限）。改完重跑 `assemble-snake.ps1` 与 `run_rules.py`，再看一眼 `snake.hex` 字数没超过 1024。

按键响应：每约 19.7 周期采样一次（2.43 kHz 下约 8 ms），事件锁存到 ACK，长按也只算一次按下沿。实际手感以现场时钟为准，M3 里和 A 一起定这个常量。

## 7. 已知限制与未验证项

- 规则与画面在自建模型上验证，**尚未在课程版 Logisim 整机运行**，M3 实玩待 B 的 SnakeIO 接进 `SnakeSystem.circ`。按计划书第 7 节，这类项目只能标"待课程版 GUI 验证"。
- 食物闪烁、分数数码管、五个状态灯、点阵行列方向都是 B 的显示侧；本程序只负责写 `FOOD`/`SCORE`/`STATE`/`ROW` 的正确值。
- 若 B 的点阵行列或位序与接口约定不同，画面会镜像或上下翻转，属显示接线问题，C 侧不改程序，按计划书第 5 节在 B 处修正。
- 计划的 Buzzer 扩展未做；接口若要改，按计划书要求先同步旧值、新值与受影响用例。
- 整机首帧依赖 A 在整机把 `SnakeIO.reset` 接常量 0、演示时把暂停计数位置 0，否则计时器不递减、蛇不动。

## 8. 给 A 的接入步骤

1. 用课程版 Logisim 打开 `snake/system/SnakeSystem.circ`，进入 `◇单周期RISC-V`，右击指令 ROM 选"加载镜像"装入 `snake/game/snake.hex`（244 字，1024 字 ROM 空间够用），保存电路。
2. 装入游戏 ROM 后 A 的 `test-native.ps1` 不再适用（它按诊断 ROM 的 PC 位置断言），要复跑诊断请先换回 `io-smoke.hex`。
3. Ctrl+R 仿真复位，把计数暂停控制位保持 0，Ctrl+K 开时钟。进到 SnakeIO 实例按"开始"。
4. 预期：复位后第 8 行亮三格、分数 00、状态待开始；按开始后向右一格吃到 (8,8)，第 8 行变 0x01E0、分数 01、食物换到 (9,8)（FOOD=0x189）。
5. 若首步不对，先查 STATE 是否被写成 1、EVENTS 是否读到 0x10，再查 ROW 的行偏移与位序（C 侧写的是 `0x1040+4*y`、bit0 最左）。
